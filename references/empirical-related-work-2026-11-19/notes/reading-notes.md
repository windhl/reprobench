# 补充实证研究阅读笔记

本轮只整理相关研究的实际内容，不据此修改 ReproBench 的定位或大纲。下面“可介绍为”是对原作的概括；“范围”用于限制引用，不能略去后再扩大主张。

## 1. Crowd-reported Vulnerability Reproducibility

**正式发表：** [USENIX Security 2018](https://www.usenix.org/conference/usenixsecurity18/presentation/mu)。本地 `crowd-reproducibility.pdf`。

**核读：** §1、§3–4 的选例和复现协议，结果解释、专家调查及 §8–10。

研究 368 个内存错误漏洞，其中有 CVE 与非 CVE 案例。五名安全分析人员按规定流程复现，并另行调查 43 名有复现经验的安全专业人士；43 不是执行全部复现实验的人数。流程覆盖资料获取、环境设置、软件准备和触发验证。

关键观察是公开报告经常缺失必要信息，而“最常缺失的信息”未必是“最难恢复、最阻碍复现的信息”。作者考察汇总多个来源的帮助，也分析仍需调试和经验推断的情况。

**可介绍为：** Mu 等通过受控的人工复现实验和专业人士调查，研究漏洞报告的信息完整性及复现困难。

**范围：** 不是 LLM 研究；主要针对有源码的内存错误，缺少 PoC 可直接按其协议计失败，且以崩溃作为主要验证信号。与自主生成 PoC、指定根因核验的成功率不能直接比较。

## 2. Web Vulnerability PoC Generation Study

**来源：** [arXiv:2510.10148v1](https://arxiv.org/abs/2510.10148)。PDF 使用期刊模板，但未核实正式期刊发表，不能按模板页眉的年份引用。旧稿 bib 已有该条目，本轮补充下载并核读。

**核读：** §I、§III、§IV 的输入条件、成功判定、任务分解、失败与上下文实验。

在 100 个可复现 Web CVE 上，比较 GPT-4o 与 DeepSeek-R1；逐步提供描述、补丁和代码，并进一步比较代码上下文粒度及反馈策略。作者预先搭建本地目标环境。基础实验要求三次生成均有效才把案例计为成功。

失败分析区分漏洞上下文、导航上下文不足以及任务识别/推理失败。导航到漏洞入口与构造攻击内容被分别分析。

**可介绍为：** Zhao 等研究公开披露信息的类型和粒度如何影响 Web PoC 生成，并分解生成失败。

**范围：** 不是仅给 CVE 的固件获取和重托管研究；受控输出或可见推理不等于直接观测模型内部因果机制。“三次全成功”也不同于 pass@3。

## 3. Enterprise Networks / cochise

**正式发表：** [TOSEM 2026，DOI 10.1145/3766895](https://doi.org/10.1145/3766895)。本地是 arXiv:2502.04227v3 作者稿。

**核读：** §3 实验与分析方法、§5 定量结果、§6 中任务传递、错误恢复与轨迹分析。

在 GOAD 企业网络环境中研究五种 LLM 配置；每种六次、每次上限两小时。定量结果与专家定性分析结合：三位渗透测试专家核读命令、输出和遗漏机会，并进行主题分析与共识讨论。

观察包括 planner/executor 间丢失关键事实、重复追逐同一攻击方向，以及错误消息如何帮助修正命令。环境是运行中的 AD 实验网络。

**可介绍为：** Happe 和 Cito 将执行日志的定量统计与专家主题分析结合，刻画自主企业渗透测试的能力和行为限制。

**范围：** 同时提出 cochise；不是脱离系统的新模型能力证明。一个网络环境的深度研究不同于多 CVE 抽样；“almost there”和线索不是已经攻陷目标。

## 4. From Capabilities to Performance

**正式发表：** [EMNLP 2025 主会](https://aclanthology.org/2025.emnlp-main.802/)。本地为会议 PDF。

**核读：** §4–6 的环境、指标、失败模式和功能增强，以及局限。

比较单一和模块化 LLM 渗透测试系统，覆盖侦察、凭据、利用、后利用、MITM 与 AD 等任务。分析错误命令、循环、上下文丢失和动态交互问题，并研究记忆、模块通信、条件调用、规划与监测等增强。

**可介绍为：** Huang 等从功能属性而非仅模型名称出发，研究不同架构的任务表现与重复失败模式。

**范围：** 含人类交互/干预指标，不能整体称为无人自主结果；部分根因与知识等级依赖作者判断。对“上下文”“推理”等解释应保留原作实验条件，不把分类当作直接测得的内部机制。

## 5. Local Privilege Escalation Interventions

**来源：** [arXiv:2604.27143v2](https://arxiv.org/abs/2604.27143)，作者注明 RAISE workshop 录用；不能称为顶会主会论文。

**核读：** §3–5、§7–9：协议、六种失败模式、增强选择、消融及局限。

在 12 个预置配置漏洞的 Debian VM 上，从执行轨迹归纳复杂命令、虚构工具、无结构探索、重复命令、忽略反馈和知识缺口。映射五种增强，并进行组合消融。每配置三次，成功比例按至少一次成功统计，near-miss 不算成功。

**可介绍为：** Probst 等以轨迹失败分类指导本地小模型 agent 的增强，并用共享 harness 下的实验比较组件作用。

**范围：** 已有低权限 SSH 入口，目标是本机提权；不是固件重建。指导条件改变了发现任务，三次重复和少量案例的差异以描述性分析为主。模型存在特定微调版本，应查实际 ID。

## 6. Decoupling Reconnaissance and Exploitation

**来源：** [arXiv:2606.25332v1](https://arxiv.org/abs/2606.25332)，未核实正式发表。

**核读：** 正文 §3–6。

构建 70 个 Web 漏洞环境；两个框架的核心比较覆盖 70 个，五框架对齐比较使用 50 个子集。侦察失败后提供正确漏洞上下文，再测试利用；另比较带或不带经验知识库的条件。

分别定义目标漏洞召回和功能性利用成功，发现存在侦察失败、补充上下文后可以利用的情况。

**可介绍为：** Yu 等通过阶段解耦和前提信息注入，分析早期侦察失败对后续利用评估的遮蔽。

**范围：** 目标容器由作者部署；部分知识条件含标准 PoC 模板。侦察召回率与利用成功率测量对象不同，不能相减称为效果提升；跨架构比较也包含具体工具与状态实现差异。

## 7. Fixed-Target Attack Consistency

**来源：** [arXiv:2605.30096v1](https://arxiv.org/abs/2605.30096)，未核实正式发表。

**核读：** §3 的 orchestrator 与指标，§4.2 失败分类、行为结果及 §5 的限制。

四种模型各运行 100 次，对固定的三服务目标观察成功、停止、阶段序列和重复性。目标包含 Juice Shop、匿名 FTP 和弱凭据 SSH。

论文纠正早期草稿：部分被日志记为 REFUSED 的事件实为上游 API overloaded_error。还明确记录各模型的温度、历史保留和批次目标 IP 并非完全一致。

**可介绍为：** Erdem 在固定目标上研究运行间波动与不同失败方式，并强调区分模型行为和服务故障。

**范围：** 单目标重复并不提供案例多样性；orchestrator 会在循环或停滞时主动提示推进，轨迹不是未经干预的模型行为。不同上下文保留等条件限制了模型间归因。

## 8. Incalmo / Multi-Host Red Teaming

**正式发表：** [IEEE S&P 2026，DOI 10.1109/SP63933.2026.00132](https://doi.org/10.1109/SP63933.2026.00132)。本地 arXiv:2501.16466v4。

**核读：** §1–3 的背景、基线与人工失败分析，§4 设计，以及评估概览与局限。

当前版本使用 40 个、每个 22–50 主机的仿真网络。参考人工解法分析 agent 日志，将行动区分为与攻击目标相关、无关或执行错误，并观察后利用脆弱性和上下文膨胀。之后提出高层任务与领域执行服务。

**可介绍为：** Singer 等从多主机攻击中现有系统的失败出发，提出更高层的计划/执行接口。

**范围：** 是新系统和 MHBench，不是纯实证论文；任务执行包含领域专门组件，成绩不能归为 LLM 单独能力。旧标题及 10 网络结果属于早期版本，不与当前版混用。

## 9. Offensive CTF Empirical Evaluation

**来源：** [arXiv:2402.11814v1](https://arxiv.org/abs/2402.11814)，未核实正式发表。

**核读：** §3–4 的任务选择、HITL/自动流程、反馈与失败分析。

从 CSAW 2023 题目中选择适合自动工作流的 26 个挑战，另研究人工交互解题和参赛者表现。失败分类包含放弃/空解、错误 flag、命令、代码、依赖和连接错误。

**可介绍为：** Shao 等比较人工参与与自动化 CTF 解题，并从实际输出构建错误分类。

**范围：** 不同工作流的人类帮助、工具和题目覆盖不同；自动化题目经过模态和交互要求过滤，不能把其与平均选手的比较推广为对专业安全分析人员的全面超越。

## 10. SecLLMHolmes

**正式发表：** [IEEE S&P 2024](https://doi.org/10.1109/SP54263.2024.00210)。本地 arXiv:2312.12575v3。

**核读：** §3 数据和 evaluator、§4 的重复性、解释与代码变换，§5 局限。

使用 228 个代码场景：48 个手工场景、30 个真实场景和 150 个变换场景；它们不是 228 个独立真实 CVE。比较漏洞判断、解释、重复回答、提示和代码变化。

**可介绍为：** Ullah 等超越单次分类准确率，系统检查安全判断的稳定性、解释一致性和对表面代码变化的敏感性。

**范围：** 不是 agent 执行研究。解释评价部分依赖 GPT-4 与文本相似性，并辅以人工验证；“解释被判一致”不等于已经证明内部推理忠实。

## 11. Agentic Repair in OSS-Fuzz / CodeRover-S

**正式发表：** [ICSE 2026 SEIP](https://conf.researchr.org/details/icse-2026/icse-2026-software-engineering-in-practice/27/Fixing-Security-Vulnerabilities-with-Agentic-AI-in-OSS-Fuzz)，DOI 10.1145/3786583.3786880。

**核读：** §1、实验协议及 §4，特别是修复正确性与未修补漏洞分析。

研究把通用编程 agent 适配到安全修复，补充动态调用图、类型和反馈；分别在历史漏洞和 45 个未修补漏洞上评价。明确区分不再触发原始崩溃的 plausible patch、人工认为正确的 patch 与维护者实际合并。

**可介绍为：** Zhang 等结合受控实验、人工正确性检查和真实项目提交，研究 agent 安全修复的实用性。

**范围：** 目标和触发输入已经由 OSS-Fuzz 提供，不涉及固件环境重建；plausibility 的比例不能直接称为正确修复率。它同时贡献 CodeRover-S，不应只当作无系统贡献的描述性研究。

## 12. Offensive Evaluation Practices（方法综述）

**来源：** [arXiv:2504.10112v2](https://arxiv.org/abs/2504.10112)，未核实正式发表。

**核读：** 方法、结果与 §6 建议。

本地 v2 回顾 19 篇研究、18 个 prototype/testbed 的来源、指标、基线、重复次数和定性分析。讨论任务进展难以简单线性化、CTF 与实践的差异，以及用预期结果而非固定命令识别子任务完成。

**可介绍为：** Happe 和 Cito 梳理 offensive-agent 实验实践，为测试环境和结果分析提供方法背景。

**范围：** 这是以文献为对象的经验性综述，不是新的漏洞复现实验。其建议是作者的方法建议，不是会议规定；数据反映当时选择的文献，旧摘要 16/15 的数字不适用于 v2。

## 只供后续比较的维度

以上研究的区别可沿五个维度核对：初始输入与环境准备责任；人类参与程度；成功和重复尝试的定义；失败标签的证据来源；描述性观察、干预实验与新系统设计的关系。暂不据此推导 ReproBench 必须采用哪种结构。
