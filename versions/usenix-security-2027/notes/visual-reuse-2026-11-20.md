## 二、逐张图片的内容和取舍

### 1. framework0724.pdf

原图左侧是 CVE/NVD/GitHub 等公共来源、30 CVE 和 reference profile；中部是五个模型、450 次运行，以及 plan.md、执行、产物和轨迹；下部是自动评分、Plan 20%、Task 80%、P1–P6 的 15/20 点配置和总分公式。

可复用的是研究材料与实际运行的组织逻辑。下部评分逻辑与当前研究目标冲突，因此没有裁掉公式后留下不完整的评分示意，而是明确改绘为三个分析维度。新图不包含模型厂商 logo、装饰角色或已完成所有核验的暗示。

### 2. prompt.pdf

原图完整列出 CVE 输入、写 plan.md、基于计划执行、写 report.md，并要求记录障碍、费用不超过 5 美元、24 小时完成、提供安装权限、输出保存到 `/output`。

这属于历史条件，适合原样保留。原图宽约 510 pt、文字约 13.4 pt；如果缩到单栏，文字会约为 6.3 pt，因此改放附录全宽，实际显示文字约 13.3 pt。正文已说明关键条件，附录保存原貌以便审查，不用图中的原始陈述代替实际 prompt/control-loop 核对。

### 3. case_study.pdf

原图描述 CVE-2020-13389：搜索、下载、提取、识别、QEMU 失败、模拟、演示。图中仍有 R1–R7、RRS=27/100、Tier 1 和百分比权重，并给出 MIPS32-LE、三次重试和未运行真实目标等细节；没有提供模型和 trial。该图在当前旧稿 `main.tex` 中所对应的 Failure Modes 章节还是注释状态，属于可用素材，不一定是实际编译主稿中的图。

这些细节不能通过删除底部分数就自动成为新稿可信证据。新稿只复用它有价值的“行动—证据”结构，替换为已核读工作区中的 CVE-2023-26315 / claude-sonnet-4-6 / 1：原组件、服务链连接拒绝、直连内部组件、保存的测试输出。保留 CASE-01 的身份/归因/重放 TODO，且不把这个例子当成模拟替代的案例。

### 4. iceberg-v4.png

原图上层是发现、复现、利用、修补；下层是 CVE ID、收集信息、获得程序、准备环境。红框统一标注“Other Benchmarks”，蓝色区域标注 ReproBench。

环境准备责任这一概念可保留在背景和相关工作，但红框范围过宽：已有 CVE-GENIE 等环境构建研究。旧图容易给读者造成所有既有工作都跳过环境构建的印象，因此没有原样迁入，也没有只改图注来覆盖图内的概括。新稿用逐项文献比较交代不同起点，Figure 1 保留本研究实际执行与材料的范围。

### 5. stagefunnel.pdf

原图标题是 best-of-three 阶段性能漏斗，数值为 P1 13.9/15、P2 9.0/15、P3 8.1/15、P4 7.6/15、P5 3.7/20、P6 2.8/20，并标注 P5 的显著下降。

这些是旧评分平均值，不是通过率、障碍频率或真实执行状态。不能删掉分母后当作“完成数量”复用。其“在哪里失去进展”的研究问题保留在 RQ1/RQ2，但图需待重新核验状态后另画；当前对应 RQ1-03、RQ2-04。

### 6. 3d.pdf

四个面板分别为全部 30 CVE 和三类各 10 CVE；横轴是 P1–P6，另一轴是模型，纵轴明确为 normalized phase score。它并非未经打分的进展比例。

数据仍依赖旧的分项得分和聚合规则，且将活动画成连续轨迹可能使人误读为同一次完整执行。新稿保留按类别、模型和活动比较的分析维度，暂不导入这些曲线；待 ANA-01 与 RQ1-03 完成后使用可验证状态和明确分母。
